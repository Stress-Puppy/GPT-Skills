# 代表性论文：时序图索引

分析历史图查询、时序图索引，或需要“如何解释最终优化算法”的具体例子时，按需阅读本文。[英文版](temporal-graph-indexing-EN.md)为默认参考。本文是分析笔记，不是额外的通用硬性要求，也不能代替阅读新论文。

## 来源与适用范围

- **[K21]** Michael Yu 等，*On Querying Historical K-Cores*，PVLDB 14(11)，2033–2045，2021。DOI：`10.14778/3476249.3476260`。依据用户提供的 `historical-kcore.pdf`，共 13 页；PDF 第 1 页对应印刷页 2033。这是会议版，结论仍将动态 PHC 索引维护列为未来工作；不能把后续期刊扩展版的算法归到本文件中。
- **[C24]** Jingyi Song 等，*On Querying Historical Connectivity in Temporal Graphs*，Proc. ACM Manag. Data 2(3)，Article 157，2024。DOI：`10.1145/3654960`。依据用户提供的 `sigmod_24_camera_ready.pdf`，共 25 页；PDF 第 N 页对应印刷页 157:N。其最终历史查询方法是 POEC-Index，最终滑动窗口方法使用 OEC-Forest。

下文页码均为 **PDF 页序**。笔记用自己的话概括原文；可迁移的分析经验是阅读后的归纳，算法名称与原文结论分别归属于所引论文。

## 术语与关键区别

| 英文术语 | 中文对应 | 在两篇论文中的含义与阅读要点 |
| --- | --- | --- |
| temporal edge / edge occurrence | 时间边／边的出现记录 | 三元组 `(u,v,t)`；同一对端点反复交互，形成多条时间记录。 |
| projected graph / snapshot | 投影图／快照 | 对闭区间 `[s,e]`，保留窗口内至少出现一次的端点对，重复出现合并成简单无向边；不是要求每条边在窗口内每个时刻都存在的交集图。 |
| historical query | 历史查询 | 查询任意历史窗口，不局限于当前窗口。 |
| sliding-window query | 滑动窗口查询 | 随新边到来而查询最近的窗口；必须核对离散／连续时间的边界约定。 |
| core number | 核数 | 顶点属于某个 k-core 的最大 k；不是顶点的普通度数。 |
| core time (CT) | core time／核时间 | [K21] 中固定起点和 k 后，使顶点进入 k-core 的最早终点；不是持续时长。 |
| start-/end-anchored query | 固定起点／终点的查询 | 固定一个窗口边界，将问题分解成更简单的一族查询；必须分清固定的是哪端。 |
| connectivity-equivalent forest | 连通性等价森林 | [C24] 中固定终点后，对每个起点阈值都保持连通分量的森林；保持的是查询答案，不是所有原始边或路径。 |
| maximum spanning forest (MSF) | 最大生成森林 | [C24] 以边时间为权重；不能误写成最小生成森林，最终有序森林也未必是生成森林。 |
| lowest common ancestor (LCA) | 最近公共祖先 | 用于解释按序向上搜索的会合位置，不一定是树根。 |
| temporal wedge transformation (TW) | 时间楔变换 | [C24] 中保持固定终点连通性等价的局部双边变换，是该文特定操作。 |

出处：[K21] §2、Definition 2.2/2.4（第 3 页）、Definition 4.2（第 4 页）；[C24] Definition 2.1–2.3（第 5 页）、4.1/4.3（第 8–9 页）、4.11（第 10 页）、5.1/5.4（第 13/15 页）。

## [K21]：PHC-Index 与 PHC-Construct*

### 问题、输入、输出

给定无向时序图、窗口 `[s,e]` 和整数 k，返回**投影图中属于 k-core 的全部顶点**（Problem 1，第 3 页）。文中的单个 k-core 是内部最小度至少为 k 的极大连通诱导子图（Definition 2.2）；返回的顶点并集可能包含多个连通分量。不能把“极大”改成“规模最大”的优化目标，也不能只返回任意一个分量。

建索引接收时序图；在线查询在已有索引上接收 `[s,e]` 和 k。Containment 子问题还接收顶点 u，只返回布尔值（Problem 2，第 4 页），不能把这个子问题当成完整的顶点集合输出。Core decomposition 和返回指定顶点所在 core，是 §4.3（第 6 页）另外讨论的扩展任务。

### 最终方法应该怎样讲

开头可用一句话提示：逐个窗口重新 peeling，或保存所有窗口，会重复大量工作。主体随后应围绕 **PHC-Index、PHC-Query，以及优化后的 PHC-Construct***，不能将 PHC-Construct 当作最终构建算法。

1. **把成员资格编码成阈值。** 对每个 `(u,k,s)`，`CT_s(u,k)` 是最早有效终点。窗口包含关系带来单调性：固定起点，扩大终点不会降低核数，所以 `[s,e]` 中的成员资格由 `CT_s(u,k) <= e` 判断（§4.1，第 4 页）。
2. **只存变化位置。** 起点向右移动时，core time 不会变小。PHC 按序记录 core time 改变时的 `(start, core-time)`，一条记录覆盖一段阈值相同的起点（§4.2，第 5 页）。这是变化记录，不是每个合法查询窗口的清单，也不能直接叫作按包含关系极小的可行窗口。文中对 k=1 直接检查窗口内是否有邻接边，用越界时间表示无法达到的阈值。
3. **通过局部有效性修复来构建。** PHC-Construct* 先初始化第一个起点的 core time，再逐步右移起点。CT-neighbor 表记录不同的支持邻居，并为重复时间边保留计数。删除一次边出现先减少计数，支持完全消失才失去该邻居。若某个 `(u,k)` 的支持邻居不足 k，就加入工作队列。LocalCT 根据不同邻居的最早贡献时间 `max(边时间, 邻居 CT)`，取第 k 小值来重算阈值，并利用时间顺序提前终止扫描。随后继续修复受影响邻居，直到队列处理完，再记录发生变化的 core time。依赖传播不可省略：局部公式本身不是独立的一遍扫描算法（§5.2，Algorithm 5–7，第 8–9 页）。
4. **恢复查询答案。** 对每个候选顶点，二分查找不超过查询起点的最后一条记录，把记录中的 core time 与查询终点比较，收集通过成员资格检查的全部顶点（§4.3，Lemma 4.11/4.13，第 5–6 页）。

值得学习的推理链是：**窗口单调性 → 阈值表示 → 压缩不变阈值 → 支持条件 → 条件失效时局部修复**。要说明省掉什么工作，以及为什么只检查较少的状态仍然足够。

### 复杂度与归属核对

区分时间边出现次数 m 与投影后去重边数 `m*`（§2）。Lemma 4.13 的 `O(log |PHC(u,k)|)` 是单点 containment 查询，不是返回所有顶点的开销；Theorem 4.14 对完整查询给出 `O(n log t_bar)`。Theorem 5.14 对 PHC-Construct* 给出 `O(|PHC| D_max)`，其中 `|PHC|` 为索引大小，`D_max` 为最大度，不能省略该因子而笼统说“线性构建”。实验中平均记录数较小，不代表对所有图都可当作常数。

## [C24]：POEC-Index 与 OEC-Forest

### 问题、输入、输出

预处理／维护接收无向时间边流。历史查询接收两个顶点 `(u,v)` 和任意窗口 `[s,e]`，返回**布尔值**，判断窗口投影图中是否存在连接它们的路径（Definition 2.2，第 5 页）。路径上的时间戳不要求递增；任务也不要求返回该路径、森林或全部连通分量。

滑动窗口查询只关注最近一段时间，所维护的状态更少。不能把覆盖多个历史终点的索引与单个当前森林混为一谈。

### 最终方法应该怎样讲

开头可以简述 MSF 能保持连通性阈值，但反复搜到树根和 reroot 会产生额外工作。详细分析应落到 §5（第 13–17 页）的 **OEC-Forest、POEC-Query、POEC-Update**。

1. **精确说明需要保持的等价关系。** 固定终点 e，对每个起点 s，仅保留标签至少为 s 的森林边，所得连通分量必须与原图窗口快照相同。这比“只保持当前完整窗口的连通性”更强。OEC-Forest 再加入固定顶点全序，非根节点满足 `parent(v) ≺ v`（Definition 4.3/5.1）。
2. **保存变化标签的有序历史。** 历史标签记录 `(父节点, 森林边时间, 记录此状态的终点时间)`，连续相同状态可以省略。边时间与历史终点用途不同。POEC-Index 保存这些历史，最新森林可从最新标签恢复（§4.1/5.1，Table 2–3）。不能仅因父节点未变，就省掉边时间已经变化的标签；Table 3 存在父节点相同而边时间不同的记录。
3. **按序查询。** 取得每个访问顶点在终点 e 的标签，然后在边时间满足起点阈值时，将 `≺` 中较大的端点向父节点推进。两端相等则为真；被树根或过旧边阻断则为假。全序使搜索在 LCA 会合，不必继续访问其上方的多余祖先（Algorithm 4，第 14 页）。用明确的序关系说明，不依赖含混的“排名更高／更低”。
4. **通过 TW 变换更新。** 将新连接与所选端点的父边组合；若新连接时间不小于父边时间，就把较新的连接作为父边，并将被替换的较旧连接继续向上传播，否则将输入连接向上传播。反复局部变换可缩短环或合并两棵树，同时保持阈值连通性和父子全序约束；变化的状态追加进历史标签（Definition 5.4、Lemma 5.5/5.7、Algorithm 5，第 15–17 页）。不能继续套用前面 MSF 的 reroot 过程，否则会破坏最终结构的全序约束。
5. **讨论滑动窗口时才展开其特化。** 只维护最新 OEC-Forest，不保留历史标签列表。阈值检查使显式删除过期边、搜索替代边不再必要；传播时间早于所需窗口时，更新可以提前终止。此时状态大小为 `O(n)`（§6，第 16–17 页）。

OEC-Forest 可能包含原图没有的变换边。森林路径是在该表示中的连通性证据，不能直接当作由输入原始边组成的路径返回。值得学习的推理链是：**查询等价性 → 压缩表示 → 全序不变量 → 缩小搜索／变化范围 → 保持等价的局部更新**。

### 复杂度与原文一致性核对

分别给历史查询、单边更新、当前窗口查询标注代价。Theorem 5.9 对 POEC-Update 给出 `O(dist(u,v))`，最坏可达 `O(n)`；§6 对滑动窗口查询给出 `O(dist(u,v))`。不能据此认为历史标签访问也总是常数时间。

所提供 camera-ready 版本有需要谨慎处理的地方：Theorem 5.3 印的是 `O(dist(u,v) · t_bar)`，而 §4.1 说明使用二分查找历史标签，Theorem 4.9 也包含对数查找因子。不能默默把印出的定理替换成自行推导的界；推导应单独说明。同样，Definition 2.3 使用 `[t_max - theta + 1, t_max]`，§6 却写成阈值 `t_e - theta`。如果边界影响例子或实现，必须说明采用的解释及原文差异。

## 可复用的分析习惯

- 先确定图语义与答案的判断条件；“temporal”一词不能替代这两项。
- 区分用户最终得到的输出、用于求出它的判定子过程，以及内部维护的索引。
- 跟随最终算法实际使用的表示和更新操作。早期算法可以作为初始化子过程保留，但不应因此成为解释主体。
- 遇到剪枝或压缩，找清冗余状态、保留的有效性依据，以及答案恢复规则；遇到增量操作，找清什么改变、什么仍有效，以及依赖如何传播。
- 核实表示究竟保持顶点成员资格、连通分量、边的身份还是原始路径，不推断比已证明查询等价性更强的性质。
- 将这些提问方式迁移到其他数据库／图论文；单调性、全序、时间语义及更新假设仍须从每篇新论文重新建立。
