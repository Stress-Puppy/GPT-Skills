# 论文问题分析

本文是 [SKILL-EN.md](SKILL-EN.md) 的中文副本；英文版为默认入口。无需同时加载两个版本。

默认用中文讲清论文究竟要求完成什么任务，再简要解释作者的最终优化方法。保留必要的英文术语和论文符号，首次出现时解释含义。用户明确指定的语言、范围和详略优先。

## 领域重点

主要面向 database、big data、graph 和 graph theory，即数据库、大数据、图与图论。从数据或图模型、查询语义、前提假设、结构性质和代价模型分析论文。数据库与索引论文应区分索引构建、查询处理、更新或维护；大数据论文只在相关时讨论 I/O、通信或分布式执行；图论论文应准确说明研究对象、约束和数学保证。

按实际需要串联“问题瓶颈 → 可利用的性质或不变量 → 最终数据结构或算法 → 正确性与代价”。使用论文中精确的专业术语，避免用空泛描述代替，并区分论文自定义术语与领域通用术语。

分析时序图时，先确认快照与路径语义：区分时间边出现记录与去重后的边、窗口投影与整个窗口持续存在、快照连通性与时间顺序约束下的可达性。分析索引时，说明每条记录编码什么、省略了什么冗余信息，以及查询如何恢复答案。对压缩或变换后的结构，应核实它保持的性质，不能默认它保留原图的边或路径。

遇到时序图索引、历史 k-core 或历史连通性问题时，按需阅读[代表性论文笔记](references/temporal-graph-indexing-CN.md)（[英文](references/temporal-graph-indexing-EN.md)）。笔记包含所提供的 2021 PVLDB 与 2024 SIGMOD 论文中的术语、最终算法示例和易错点，不能将其当作所有图论文的统一假设。

## 阅读与取证

1. 确认论文标题及所读版本。对上传文件读取正文；对网址打开原始页面并取得对应全文。检索同一论文的公开版本可以用于获取正文，但不能把预印本、会议版、期刊扩展版混为同一版本。若链接对应多篇文章或版本差异会影响回答，先澄清目标。
2. 先浏览摘要和引言定位任务，再阅读相关预备知识、问题定义、方法、优化章节及必要的定理或附录。理清从 baseline、中间方法到最终优化算法的演进，不停留在最早出现的框架或伪代码。不能仅凭标题、摘要或搜索摘要补全正式输入输出。
3. 为问题定义、约束及核心方法记录原文位置。关键陈述附章节名、Definition/Algorithm 编号或页码；网页来源提供原始链接。本地 PDF 使用页码时说明采用 PDF 页序还是论文印刷页码，不猜测编号。
4. PDF 文本提取丢失公式、上下标、表格或图中信息时，查看对应页面；扫描件需要 OCR 并核对关键内容。资料获取和提取工具按当前环境选择，不绑定某个第三方插件。
   若定义、例子、伪代码或复杂度陈述不一致，应交叉核对，并说明影响结论的不一致之处。区分自己的还原或推导与论文实际写出的结论。
5. 若无法获取全文，说明当前实际读到的范围，只报告能确认的内容，并请用户提供 PDF 或关键段落。把未核实项标为“无法从当前资料确认”，不编造定义、算法或结论。

## 分析要点

### 研究问题

- 用“给定……，在……条件下，求／判断／维护……”写出具体任务，不能只说“提高效率”“研究图数据”这类背景目标。
- 解释研究对象、关键定义、可行解条件，以及有无需要最大化或最小化的目标。区分硬约束与优化目标、极大与最大、一个解与全部解、精确结果与近似结果；只解释论文实际涉及的区别。
- 简要说明难点，以及本文是在定义新任务，还是为已有任务提出新算法、索引或系统。没有充分证据时不宣称“首次提出”。

### Input

- 列清数据对象、数据模型、查询、参数，以及影响问题含义的假设；说明每项是什么、代表什么、起什么作用。
- 不把实验数据集名称当作形式化输入；例如“图 G、查询顶点 q、阈值 k”比“若干真实图数据集”更准确。
- 如果包含预处理／建索引与在线查询，分别说明各阶段接收的输入；如果含训练与推理，也分别说明。只展开论文中确实存在的阶段。
- 参数的范围、时间窗口边界、方向性等细节在影响答案时必须解释；未规定的内容不要自行补充。

### Output

- 明确返回对象及形式，例如布尔值、数值、路径、顶点集合、子图、全部满足条件的结果、排序列表或模型；补充成立条件与结果数量要求。
- 输出必须与 Input 对应，能回答“输入这些东西后，用户最终拿到什么”。区分最终答案、算法中间结果和论文贡献；索引通常是查询手段，是否属于任务输出以正文定义为准。
- 决策、枚举、优化、维护等任务分别说清“判断什么／列举什么／优化什么／更新后保持什么”。如正文规定无解或空结果时的行为，简要说明。
- 对没有算法式输入输出的理论、实证或综述论文，明确说明这一点，改用“研究前提或研究材料 → 待证明结论或研究产出”解释，不强行编造计算任务。

### 解决思路

- 简要或详细的技术分析都默认以最终优化算法为主。明确给出该方法或最终变体的名称及定义所在章节。Baseline 或最初思路可在开头用一两句话提供直觉和动机，不应占据主要技术分析篇幅。
- 不能详细讲完中间框架后，只在末尾列举几个优化名称。应把优化融入数据结构与处理步骤，解释最终方法实际怎样运行。
- 先用一句话说最终方法的核心思想，再用通常 3–5 个简短步骤解释从输入到输出的过程。说明最终结构保存或有意省略什么信息、依赖什么关键性质或不变量，以及相关的构建、查询、更新过程。用户需要深入 tech 时，继续展开最终算法的这些部分。
- 对每项关键优化，解释它针对什么瓶颈、如何减少或省去工作，以及为什么仍能保证答案正确。区分内部使用的数据结构与任务要求的输出，避免只罗列算法名、缩写或“剪枝、索引、优化”等词。
- 如果有多个最终变体，应按适用场景、理论保证或论文报告的实际表现区分。论文对当前场景有推荐方法时以它为主；否则说明共同的最终框架和重要差异，不自行选出唯一赢家。不能把某个变体的步骤与另一变体的复杂度或实验结果混用，也不能仅因某算法最后出现就认定它是最终或首选方法。
- 默认不展开证明、逐行伪代码、完整实验或复杂度推导。复杂度有助于解释方法时，明确归属的最终变体和操作，按实际情况区分最坏情况与均摊界，定义符号并使用清楚的写法，如 `O(n + log^2 m)`。

## 默认呈现方式

先写论文标题和所读来源／版本，再依次回答下列四项；不适用的内容直说，不凑格式。小标题使用回答语言：

1. **研究了什么问题**：先给直白描述，再给精确任务与关键条件；用少量篇幅说明难点。
2. **Input 是什么**：适合时用“输入项｜含义｜作用或条件”的小表格列出。
3. **Output 是什么**：说清返回对象、满足条件和优化目标。若定义抽象，可附一个很小的自拟输入输出示例，明确标注“示意例子”，并核对它满足原文约束。
4. **怎么解决的**：点明最终优化方法，给出核心思想，并将关键优化融入处理步骤。仅在有助于说明直觉或瓶颈时，在开头简短提及 baseline。

篇幅优先留给问题、输入、输出；方法部分保持简洁。多篇论文逐篇说明，不主动混成对比综述。没有额外要求时直接在对话中回答，不额外生成报告文件、研究选题或文献综述。

## 从代表性论文中学习

用户明确将论文作为改进本 skill 的代表性材料提供时，从正文中提炼可复用的专业术语、内容分析方式和问题／算法思维方式。记录英文术语、恰当的中文对应及定义，并为可复用经验标注论文版本与原文位置。区分领域层面的指导与单篇论文特定的模型或算法，不把一篇论文的假设推广到整个领域。

阅读指定论文后，再按需要补充精简的参考笔记，从本 skill 中链接并说明适用场景，同时保留英文和中文版本。不大段复制论文，不声称已经学习尚未提供的论文。普通论文分析请求本身不代表用户要求更新 skill。

## 交付前核对

确认读者能依据解释判断一个给定对象是否是合法答案；确认所有关键参数和输出条件均有原文依据；确认方法确实对应所述问题。核对技术解释对应最终优化算法实际存储的信息与执行的操作，且每个复杂度都归属于正确变体。将自己的解释性推断与作者明示的定义分开，保留资料缺口，不把未核实内容写成事实。
